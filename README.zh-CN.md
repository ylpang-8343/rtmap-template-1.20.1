# RTMap

面向生电玩家（做农场、机器和红石的玩家）的地图模组。全屏地图、小地图，以及史莱姆区块、刷怪范围、传送门、区块加载和服务器负载的一套工具，都在同一个 Fabric 模组里。

[English](README.md)

> **状态：早期开发。** 目前由一个人在做，Modrinth 和 CurseForge 上还没有发布版本，只有作者自己测试过，主要是在单人游戏里。先做 Minecraft 1.20.1，之后再升级到更新的版本。

## 它能做什么

**地图**
- 全屏地图（按 `M`）和小地图。地图随探索自动生成，使用原版地图配色，按世界和维度分别保存，所以不同世界、不同服务器的地图不会串。
- 可以从很近一直缩到 0.01 倍，缩小后地图也不会糊成一团。保存分块时会同时生成缩略层，缩得很远时开销也很小。
- 小地图：默认方形、在右上角、锁定北方；位置、大小、是否旋转和是否显示坐标都可以改。

**地图上可以开关的图层**
- 史莱姆区块、刷怪范围（24 格和 128 格）、下界传送门链接范围、路径点和玩家位置。
- 区块加载：哪些区块被加载、加载到什么程度（实体加载、方块加载、边缘加载），以及是什么让它们保持加载（强制加载、传送门、出生点、玩家）。
- 区块负载热力图：按每个区块里实体、方块实体和漏斗的数量估算，权重取决于区块真正在运行多少。这是按数量估算的，不是实测的耗时。
- 区块耗时：启动一次 5 到 60 秒的分析，看每个区块占用了多少服务器时间，并拆分成实体、方块实体、计划刻、随机刻、刷怪和方块事件。
- 测量工具：尺子、矩形和圆，给出长度、面积、区块数和区域文件数。

**维度与分层**
- 下界有地形：地图显示最上层空间的地面，就像把屋顶掀掉后看到的样子，岩浆用亮橙色。有一个开关可以改成显示屋顶，以及建在屋顶上的东西。
- 左边有一条层条，用来选择看这个维度的哪一个 16 格的层，主世界、下界和末地都可以。地图也能跟着你：在地下显示你所在的层，在地面显示地表。
- 地下的层**只画洞穴**（开放空间和流体）。实心岩石有意留空，所以这张地图不能当 X 光用。

**路径点**
- `B` 创建，`N` 打开管理器。可以分组（整组开关）；死亡路径点走回去就会自动移除；世界里有光柱和名牌，还能显示距离。
- 可以在聊天里分享（是否发送由你决定，收到的路径点绝不自动添加）、导出导入文件，也可以用可配置的命令传送。
- 主世界与下界之间会自动换算坐标（光标、小地图和另一维度的路径点）。

**服务器信息（可选的服务端部分）**
- 状态栏里的服务器 MSPT 和 TPS、史莱姆区块用的世界种子、区块加载与负载数据、区块耗时。
- OP 自动获得；其他人需要服主打开对应开关。见[在服务器上使用](#在服务器上使用)。

## 运行要求

- Minecraft 1.20.1
- Fabric Loader 0.19.5 或更新
- 1.20.1 的 [Fabric API](https://modrinth.com/mod/fabric-api)（开发时用的是 0.92.12）
- Java 17 或更新

客户端和专用服务端用同一个 jar。服务端部分是可选的：没有它，所有客户端功能照常使用，需要服务端信息的功能只是不提供。

## 安装

目前还没有发布版本。想试用的话请自己构建（见[构建](#构建)），把 `build/libs/rtmap-1.0.0.jar` 和 Fabric API 一起放进 `mods` 文件夹。

## 按键

| 按键 | 作用 |
|---|---|
| `M` | 打开或关闭全屏地图 |
| `B` | 新建路径点（在地图上是光标所在位置，否则是你的位置） |
| `N` | 路径点管理器 |
| `=` / `-` | 小地图放大 / 缩小 |
| 未绑定 | 显示或隐藏小地图 |

都可以在“控制”里的“RTMap”分类下修改。

全屏地图上：拖动平移，滚轮以光标为中心缩放，双击空白处创建路径点，点路径点编辑，右键打开菜单（新建路径点、复制坐标、传送；对路径点还有编辑、分享、删除）。顶部工具栏放着图层开关、测量工具、缩放、路径点管理器和设置，悬停可以看名称。设置界面支持搜索。

## 在服务器上使用

客户端功能在任何服务器上都能用，装不装服务端部分都一样。需要服务端部分的有：

| 内容 | 谁能获得 |
|---|---|
| 世界种子（史莱姆区块） | OP；其他人需要开启 `seed_sharing`。单人游戏和自己开的局域网世界直接读取种子。也可以手动输入种子作为备用 |
| 区块加载、负载热力图、MSPT | OP；其他人需要开启 `chunk_data_sharing` |
| 区块耗时 | 只有 OP，并且要开启 `chunk_profiling`（默认开启） |

服务端设置在 `config/rtmap-server.json` 里，客户端永远无法读取或修改。

| 键 | 默认值 | 含义 |
|---|---|---|
| `seed_sharing` | `false` | 非 OP 也能获得种子 |
| `chunk_data_sharing` | `false` | 非 OP 也能看区块加载、负载数据和 MSPT |
| `chunk_profiling` | `true` | OP 可以启动区块耗时分析 |
| `command_permission_level` | `3` | 使用 `/rtmap` 需要的权限等级（2 到 4） |
| `seed_request_limit`、`seed_request_window_seconds` | `3`、`30` | 种子请求的限频 |

命令（需要上面的权限等级）：`/rtmap seed_sharing [true|false]`、`/rtmap chunk_data_sharing [true|false]`、`/rtmap chunk_profiling [true|false]`、`/rtmap reload`。

从服务器收到的种子只保存在内存里，从不写入磁盘。网络协议见 [docs/network-protocol.md](docs/network-protocol.md)。

## 文件

| 位置 | 内容 |
|---|---|
| `config/rtmap-client.json` | 你的设置：小地图、图层、路径点显示、传送命令等 |
| `config/rtmap-server.json` | 服务端设置（见上） |
| `rtmap/maps/<世界>/<维度>/` | 保存的地图分块。维度的其他视图（屋顶、每个层）在其中的 `layer-*` 文件夹里 |
| `rtmap/maps/<世界>/` | `waypoints.json`、`portals.json`，手动输入过种子的话还有 `seed.json` |
| `rtmap/exports`、`rtmap/imports` | 导出或导入的路径点文件 |

读不出来的文件会保持原样，绝不会被覆盖。

## 构建

```
./gradlew build
```

模组按 Java 17 编译，但 Gradle 本身（Fabric Loom 1.18）需要在更新的 JDK 上运行，我们用的是 25。如果你默认的 Java 比较旧，可以在 `~/.gradle/gradle.properties` 里用 `org.gradle.java.home` 指向新的 JDK。`./gradlew runClient` 会启动开发用客户端。

## 与其他模组的关系

RTMap 借鉴了 Xaero's Minimap 和 World Map、JourneyMap、MiniHUD 的功能思路，也参考了公开资料里区块加载与服务器负载的展示方式。它与这些模组都没有关联，也没有包含它们的任何代码、素材或文件格式。与其他模组的兼容性还没有测试过。
